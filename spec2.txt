Design Spec: Modular tpt-appfront Ecosystem UpgradeStatus: DraftTarget Repository: tpt-solutions/tpt-appfrontLicense: MIT OR Apache-2.0Maintainer: TPT Solutions1. Summary & Motivationtpt-appfront provides a unified UITree abstraction for multi-target rendering (DOM, Canvas, TUI, HTML, AI Schema). This spec proposes a strictly modular, opt-in upgrade. Developers pull in only the crates they need, avoiding bloat.Crucially, this spec defines how tpt-appfront integrates as a first-class Rust-native frontend for the tpt-pwa / tpt-cortex ecosystem, allowing developers to build offline-first, app-store-free applications entirely in Rust.2. Core Philosophy: Lean & Opt-InEvery feature is a separate crate. Developers compose their exact stack:# 1. The absolute minimum (core UI tree)tpt-appfront = "0.1"# 2. Add visual design (opt-in)tpt-appfront-theme = "0.1"# 3. Add 3D viewports (opt-in)tpt-appfront-canvas-3d = "0.1"# 4. Integrate with tpt-pwa / tpt-cortex (opt-in)tpt-appfront-cortex = "0.1"3. Proposed Architecture: Modular Crates3.1. The Core (Unchanged)tpt-appfront (umbrella crate)Re-exports tpt-appfront-core.No new features added to core. It remains the pure, lightweight UITree AST and rendering abstraction.3.2. Ecosystem Integration Crate (The PWA Bridge)tpt-appfront-cortex (Native PWA Superpowers)Role: The bridge between tpt-appfront (running in Wasm/Browser) and the tpt-cortex native companion (Go daemon + Rust VM).Dependencies: tpt-appfront-core, serde, serde-wasm-bindgen, wasm-bindgen-futures, web-sys (WebSocket).Key Components:Capability Negotiation Hook: A single, clean branch point: CortexClient::is_daemon_reachable().JSON-RPC Client: Typed, statically-checked bindings to the tpt-cortex JSON-RPC contract (e.g., client.execute_task(".ctx bytecode")).Graceful Degradation Wrapper: A CortexAware component that automatically renders a "Syncing offline..." fallback UI using standard Web APIs (IndexedDB) if the daemon is unreachable, and seamlessly switches to native execution when it connects.Zero native dependencies: Compiles cleanly to Wasm for the browser, and does nothing/no-ops when compiled to native TUI/Canvas targets.4. API Design: Modular Usage in ActionScenario A: Minimal Standalone Appuse tpt_appfront::prelude::*;fn minimal_view() -> UITree<Msg> {    UITree::container(|c| {        c.heading(1, "Hello World");        c.button("Click").on_click(Msg::Click);    })}Scenario B: Themed + Animated Appuse tpt_appfront::prelude::*;use tpt_appfront_theme::prelude::*;use tpt_appfront_animate::prelude::*;fn themed_view() -> UITree<Msg> {    ThemeProvider::active(|c| {        c.themed_button("Click Me")         .variant(ButtonVariant::Primary)         .animate(Transition::spring().duration(300));    })}Scenario C: Offline-First PWA with tpt-cortexuse tpt_appfront::prelude::*;use tpt_appfront_cortex::prelude::*;#[derive(Debug, Clone, PartialEq)]enum Msg {    RunBackgroundTask,    TaskComplete(String),}fn pwa_view() -> UITree<Msg> {    // CortexAware handles the "is daemon reachable?" branch automatically    CortexAware::new(|ctx| {        if ctx.is_reachable() {            // Render native-powered UI            ctx.container(|c| {                c.heading(2, "Native Mode Active");                c.button("Run Secure Local Task").on_click(Msg::RunBackgroundTask);            })        } else {            // Render graceful degradation UI            ctx.container(|c| {                c.heading(2, "Offline Mode");                c.text("Task queued for local sync when companion connects.");            })        }    })}5. Implementation PhasesPhase 1: Foundation & Taste (Months 1-2)tpt-appfront-theme (trait, registry, file loading, default theme).tpt-appfront-animate (spring physics, backend adapters).tpt-appfront-focus (keyboard nav, focus trapping for kiosks).Phase 2: Enterprise & PWA Bridge (Months 3-4)tpt-appfront-cortex (JSON-RPC client, capability negotiation, graceful degradation).tpt-appfront-virtual (virtualized lists).tpt-appfront-forms (declarative validation).Phase 3: 3D & Global (Months 5-6)tpt-appfront-canvas-3d (3D viewport node, SceneDelegate).tpt-appfront-i18n (internationalization, RTL).tpt-appfront-responsive (breakpoints, PWA-optimized viewport handling).Phase 4: Polish & Showcase (Month 7)Update tpt-appfront-templates to showcase modular combinations.Build a demo PWA in the tpt-pwa repo that uses tpt-appfront + tpt-appfront-cortex instead of Svelte, proving the Rust-native frontend works flawlessly with the Go daemon/Rust VM.Ensure cargo-deny passes for all new dependencies.6.
